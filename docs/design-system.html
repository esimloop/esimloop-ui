00 — Cover

Two design systems for one SEO product: the app and the public site

A faithful reconstruction of the OpenSEO visual language, rebuilt as brand-neutral tokens and components. Values come from the open-source implementation first, the running product second, and visual inference only where neither answers.

Primary source

Tailwind CSS v4 + daisyUI 5.5.19 theme declarations in the application stylesheet, plus 40+ component implementations read directly from the repository.

Character

Flat. Grayscale base with a single blue accent. Separation by hairline border, never by shadow. Small type, tight rows, numerals in tabular figures.

Scope

Both layers. Sections 01–10 cover the application; section 11 covers the public site, which is a genuinely separate system. They share a typeface and nothing else.

How to read this document. Every colour, size and radius below is a token, and every component consumes tokens only. Where the original leans on a framework default, the computed value is written out so the system can be rebuilt without that framework. Deviations and unverifiable values are listed at the end under Open questions.

Tablet · 768–1023px

  • The sidebar is present in full from 768px — there is no intermediate rail. It keeps its 240px, so the content column loses that width rather than the sidebar compressing.
  • Page padding steps up to 24px at 768px and does not change again.
  • KPI rows drop from four columns to two.
  • Tables keep every column and gain horizontal scroll inside their container.
  • Page-header actions stay on the same row as the title from 640px up.

Mobile · below 768px

  • The sidebar becomes an overlay drawer: the same 240px component, positioned at the leading edge over a 45% black scrim, opened from a hamburger and closed by the scrim, a close button, or navigating.
  • A top bar appears — the only breakpoint that has one. 44px tall, on surface.card with a bottom hairline: hamburger, then the wordmark.
  • The panel loses its cutout: no radius, no top or left border, since it now fills the width.
  • Page padding returns to 16px.
  • Wide pages that pair a table with a detail view split into a two-tab switch (for example Keywords / SERP analysis) rather than stacking both.
  • Filters collapse into a toggled panel with a single-column text grid and a two-column numeric grid.
  • Tables keep their columns and scroll horizontally — see 07 for why this is the right call for this system.

Site audit issue

Three severities, not five. The product models issues as critical, warning and info, and adds a passing state for checks that found nothing. A five-tier scale would need new colours the palette does not contain, so the three-tier model is canonical here; a mapping for teams that need five tiers is given below.

Issues are grouped by type, then sectioned by severity in fixed order. A section header carries a 6px dot, an 11px uppercase label and a count. Each group row shows an 8px dot, the issue title, the affected-page count and a chevron; expanding it reveals the explanation, the fix, and the affected URLs, and applies a 2px left rule in the severity colour.

Rank tracking row

Responsive rules

Four breakpoints, but only one of them is structural. Everything that matters happens at 768px, where the sidebar appears and the panel gains its cutout.

Tables on mobile — horizontal scroll

The system keeps the table and scrolls it sideways. It does not reflow rows into cards, drop columns, or hide data behind disclosure. This follows the product, and the reasoning holds: these tables exist to be compared across — volume against difficulty against position. Card reflow destroys the column axis that comparison depends on, and a hidden column is a metric the user cannot sort by. Scrolling costs a gesture; the others cost the task.
  • The table keeps its intrinsic minimum width and scrolls inside its own container. The page body never scrolls sideways.
  • The identifier column takes a minimum width (192px) so the keyword stays readable while the numeric columns scroll past it.
  • Density drops to the compact variant so more columns fit before scrolling starts.
  • Row actions collapse into a single overflow button; bulk actions move to the floating bar, which is already full-width-aware.
  • Where a page pairs a table with a detail view, mobile splits them into two tabs instead of stacking — the table keeps its full height.

09 — Accessibility

Accessibility

Measured, not assumed. Every ratio below was computed from the resolved token values. Three of them fail, and the fixes are stated rather than left to interpretation.

Measured contrast

text.primary on card18.1:114.7:1AAA both themes.

text.muted on card4.7:16.1:1AA both — but only just in light. Do not push below 60%.

The one palette change this system needs. The four feedback hues are shared across themes and were tuned against the dark ground. In light they are decorative-strength, not text-strength. Either accept the rule above — semantic hue as fill, border and dot; foreground colour for the label — or add light-theme text variants at roughly oklch(45% …) for the same hues. The reconstruction keeps the original values and enforces the rule, so nothing shifts visually.

Requirements

  • Field focus needs a second signal. The accent border plus tint is colour-only, so it does not meet non-text contrast on its own against the resting border. Add a 2px accent outline at 2px offset on :focus-visible for keyboard users while keeping the tint for everyone — pointer users see no change, keyboard users get a ring.
  • Never status by colour alone. Every status in this system already carries a second channel and must keep it: severity has a dot and a section label; rank movement has an arrow and the literal words lost; deltas have ▲ and ▼ glyphs; intent badges carry an abbreviation. Difficulty scores carry the number itself.
  • Targets. The 24px compact button is below the 24×24 minimum only when its hit area is not padded — give every xs control at least 24×24 of hit area, and 44×44 on touch. Table row checkboxes are 16px visually and must be wrapped in a 24px hit area.
  • Tables. Real <table> markup with <th scope>. Sortable headers are buttons with aria-sort on the header cell. Selected rows carry aria-selected. The selection column header is a checkbox with a label, not an empty cell.
  • Icon buttons always carry an aria-label and a tooltip with matching text, so pointer and screen-reader users get the same name.
  • Destructive actions name the object in the button, confirm in a dialog that states what is lost, and sit in a bordered danger zone when they live in settings.
  • Keyboard. Tab order follows the visual order: sidebar, then toolbar, then table, then pagination. Escape closes tooltips, menus, modals and the drawer. Focus moves into a dialog on open and returns to the trigger on close.
  • Truncation. Any truncated cell carries the full value in title, and long URLs keep their direction with dir="ltr".
  • Zoom. Inputs are 16px minimum on coarse pointers so iOS does not zoom on focus. Page zoom is never blocked.
  • Motion. Everything animated is colour or opacity, so prefers-reduced-motion costs nothing to honour — and it is honoured.
10 — Principles

Design principles

The rules that decide the cases this document does not cover. If a new component is ambiguous, these settle it.

Borders separate, shadows float

Anything in the page plane gets a 1px border and no shadow. Shadow means the element is above the page: menu, tooltip, modal, drawer, bulk bar. Adding elevation to a card is the fastest way to break this system.

Density is a feature

More rows on screen means fewer scrolls between comparisons. Reach for the compact table before a narrower page. Whitespace is spent on separating groups, not on padding individual rows.

Colour is information

One accent, four feedback hues, and a difficulty ramp that means something. No decorative colour, no gradients, no tinted cards. If a colour does not encode a value or a state, it does not belong.

Numbers get numeric treatment

Measured values are right-aligned, tabular or monospace, and formatted compactly. Monospace marks a measurement, not code. A missing value is an em dash in faint — never a zero.

The data is the interface

No global header, no hero, no oversized metric tiles. Chrome is trimmed until the table can start near the top of the panel. On research pages the query replaces the page title entirely.

Say what happened

Empty states name the reason and offer the way out. Errors say what failed and what it cost. A lost ranking says lost. Nothing is left for the user to infer from a colour or a blank cell.

11 — Marketing

The marketing layer

A second, deliberately separate system for the public site. It shares the typeface with the application and nothing else — different palette, different type scale, different button, different elevation rules, and light-only by design.

Why two systems rather than one. The application optimises for comparing many numbers in little space: flat, grey, 11px tables. A marketing page optimises for one message at a time: warm ground, 72px display type, generous bands. Forcing either to serve the other's job weakens both. The original draws exactly this line, and this reconstruction keeps it — the two layers are namespaced (ds- and mk-) so they can coexist in one repository without colliding.

Comfortable table densityExtensionThe framework supports it; the product uses only the compact and default variants. Included for short reference tables.
BreadcrumbsReconstructed by conventionDetail routes are nested, but a dedicated breadcrumb component was not found. The one specified uses the system's own text tiers, 12px chevron and current-page treatment.
Feedback colours in light themeKnown limitationWarning and info fail AA as text on white, and success and error pass only at large sizes. The reconstruction keeps the original values and constrains their use (fill, border, dot — never small text). If AA for coloured text is required, add light-theme variants near oklch(45%) for the same hues; this is the only change that would alter the palette.
Marketing display faceSubstituted in the originalA comment in the marketing stylesheet states that Inter is standing in for Saans, which is the intended display face and is a commercial licence. Every size, weight and tracking value in section 11 was tuned against Inter as it actually ships, so the reconstruction is faithful to what renders today. If you licence Saans, re-check the tracking — it is a narrower face and the -0.028em on the hero will likely need loosening.
Marketing dark themeAbsent by designThe public site is light-only. The code goes out of its way to re-pin light values on a wrapper class, because the shared framework would otherwise let an OS dark preference leak in and flip the documentation tokens. Section 11 keeps that decision: it declares no dark palette. Adding one is a real design project, not a token swap — the four warm bands have no dark equivalents.
Pricing pageNot reconstructedA featured-plan surface is declared in the marketing tokens (#221F1B, shared with the terminal) but the pricing page layout itself was not audited. If you need a pricing template, that card is the one component to source before building it.
Chart library specificsReproduced, not portedThe original renders charts with a React charting library at a fixed 210px height, 12 data points, animation disabled, hidden axis lines and a 44px Y-axis gutter. Those measurements are reproduced here in plain SVG; a library implementation should match the same geometry and read the same chart tokens.
